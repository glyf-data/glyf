# glyf Governance

This document describes how glyf is organised and how decisions are made.

---

## Overview

glyf is maintained by a single owner, **Kannan Kalidasan**, who holds final authority over the project. This is sometimes called the BDFL (Benevolent Dictator For Life) model - common and appropriate for early-stage open source projects.

The project is organised around three kinds of participants:

- **Owner** - sets direction, makes final decisions, manages licensing and scope
- **Contributors** - anyone who submits a pull request or opens an issue
- **Users** - anyone using the project

There are no committees, voting processes, or consensus requirements at this stage.

---

## Owner

**Kannan Kalidasan** is the owner and sole maintainer of glyf.

The owner has final authority over:

- Technical direction and architecture
- What contributions are accepted or declined
- Project scope - what belongs in this repo and what does not
- Licensing, now and in the future
- This governance document itself

The owner holds copyright over the project. The repository lives at <https://github.com/kannandreams/glyf> and may move to a GitHub organisation owned by the same person in future - ownership and governance remain unchanged if that happens.

## Contributors

Anyone is welcome to contribute. Pull requests, bug reports, and thoughtful issues are appreciated.

All contributors must accept the [Contributor License Agreement](./CLA.md) before any substantive contribution is merged. The CLA is a license grant to the project owner; contributors retain copyright and authorship in their contributions while granting the project owner the rights needed to maintain, distribute, sublicense, relicense, and commercialize the project over time.

Contributions are reviewed and accepted at the owner's discretion. See [CONTRIBUTING.md](./CONTRIBUTING.md) for what is in scope, what is not, and how to submit.

There are no formal contributor roles or elevated privileges at this stage. That may evolve as the project grows, and this document will be updated if it does.

---

## Decision Making

Decisions are made by the owner. Community input via issues and discussions is genuinely welcome and will be read - it is not binding.

For technical proposals, opening an issue to discuss before writing code is strongly encouraged. It avoids wasted effort and gives the owner a chance to flag if something is out of scope early.

---

## Changes to This Document

The owner may update this document at any time. Changes will be committed with a clear message. As the project grows, governance may evolve - any meaningful changes will be communicated in the project's discussion forum or release notes.
